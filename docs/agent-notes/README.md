# Agent notes

Implementation plans written while building the features in this repo. Each file
was drafted before the code and kept after it, because they record the reasoning
that commit messages cannot hold: what was tried, what was rejected and why, and
which commits landed the result.

They are working documents, not polished documentation. Dates are in the filename;
commit hashes inside them are the checkpoints to read alongside `git log`.

These were written in long sessions with an AI agent. The human side was the
product decisions, the scope calls, the testing on real managed Chromebooks and
every deploy; the agent side was drafting plans, writing most of the code to
spec, and keeping the documentation in step. Keeping the plans in the repo is
part of that disclosure: you can see the working method, not just the output.
