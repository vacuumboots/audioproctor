Use Cases

Who uses AudioProctor and how.

AudioProctor is for any assessed student who needs audio support: students with reading disabilities, English Language Learners in applicable assessments, and students with IEPs or designations requiring an audio accommodation.

Provincial Assessment

IEP or designation requiring audio

A student has a designation requiring audio support during provincial assessments. The teacher uploads the official audio track — or records their own read-aloud — and shares the access code for the assessment window. The student uses the extension during the exam on their managed Chromebook.

Free tier — one teacher, no commitment.

Small School

Flexible accommodation without infrastructure

Schools with only a few accommodation students don't need a full assistive tech platform. One teacher, one upload, one code. There's no provisioning, no student accounts, and no coordination with IT for each assessment.

Free tier — one teacher, no commitment.

Division Rollout

IT deploys once, every school has it

Common Questions

Things divisions ask before signing.

Does this work on any Chromebook?

Yes. AudioProctor works on any Chromebook running Chrome OS. For managed devices, IT can force-install the extension through Google Admin Console so teachers don't need to do anything. Unmanaged Chromebooks can also install it manually from the Chrome Web Store (coming in a later release).

Do students need accounts?

No. Students never sign in. They enter a short access code — given verbally by the teacher — and the extension opens directly to the audio player. There is no student-facing login, no email required, and no account creation.

Who can see uploaded audio files?

Only the teacher who uploaded the file. Files are stored in a private storage bucket, and access is controlled by row-level security tied to the teacher's Google account. Even the access code doesn't reveal the file — it only works through our API, which verifies the code and generates a short-lived link.

What happens when the access code expires?

Files and codes expire automatically after 7 days by default (the division tier allows custom expiry windows). When an upload expires, the access code stops working and the audio file is deleted from storage. Teachers can also delete uploads manually at any time from the dashboard.

Is this compliant with Alberta FOIP?

AudioProctor does not trigger a Privacy Impact Assessment under Alberta's FOIP Act. No student personal information is collected or stored at any point — students are completely anonymous to the system. The only personal data processed is teacher email addresses, which are already covered by existing Google Workspace agreements at participating divisions.
